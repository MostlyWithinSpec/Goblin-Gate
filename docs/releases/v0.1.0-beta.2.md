Fixes from the first week of running Goblin Gate as a home firewall in place of pfSense.

## Fixes

- **Deleting an object that is still in use is refused, with the reason.** Deleting an address, group,
  service, schedule, threat feed or security profile that a policy (or a group or DNS filter profile) still
  uses used to succeed, and the next commit then failed. Now the page says what still uses it, for example
  `"Kids_Devices" is still used by policy 14 "wifi-rule-14". Remove it there first.`, and every delete asks
  for confirmation first.
- **Commit errors name the policy.** A policy problem now reads
  `policy 14 "wifi-rule-14": unknown src_addr reference "Kids_Devices" (deleted or renamed?)` instead of
  pointing at `policies[11]`.
- **Firewall Policy: the row actions are always visible.** The ⋮ menu (clone, insert, disable, delete) stays
  pinned to the right edge of a wide table, and its menu is no longer cut off by the table's scroll area.
- **IPS uses no more queues than the box has CPU cores** (at most 4 per profile). On a 2-core box Suricata
  warned that it ran more queues than cores, which slows it down.
- **A domain list set up as an IP threat feed says so.** pfBlockerNG often lists hosts files as IP lists;
  such a feed used to fail with "no valid entries". It now says how many domain names it found and that it
  should be a domain feed used in a DNS filter profile.
- **pfSense import: IPv6 tracking without upstream IPv6 stays off.** When a LAN tracked a WAN that had no
  IPv6 in pfSense, the import turned DHCPv6 on for the WAN; with an ISP that offers no IPv6 the LAN then
  waited for a prefix forever. IPv6 is now left off, as it was in pfSense in effect, and the report says how
  to turn it on.
- The "wait for network" step at boot no longer shows as a failed service when no link is up yet (first boot
  before setup, WAN cable unplugged); services start either way.

## Upgrading

Boxes on the beta channel see this version within 6 hours (System → Updates, or `apt-get update && apt-get
install goblin-gate goblin-gate-plugin-sentry` as root).

## Install

Download `goblin-gate-0.1.0-beta.2-amd64.iso` below, boot it (BIOS or UEFI, Secure Boot works), pick the
disk, and open `https://<LAN address>` to run the setup wizard.
