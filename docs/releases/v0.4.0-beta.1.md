The first beta towards 0.4.0: single sign-on and custom admin roles, UniFi device details, BGP and
OSPF, site-to-site VPN between gates, a captive portal for guests, RADIUS with a VLAN per device, and
a Terraform / OpenTofu provider.

This is a beta. Boxes on the stable channel stay on 0.3.0; pick **beta** under System → Updates to try it.

## New

**Admin access**

- **Single sign-on** (System → Admins → Single sign-on): log in to the web UI through Authentik, Keycloak,
  Authelia, Microsoft Entra ID, Google or any OpenID Connect provider. Users get their role from their
  groups at every sign-in; nobody gets an account on the gate, and local accounts keep working. See the
  wiki page *Single Sign-On*.
- **Custom admin roles** (System → Admins → Roles): give a role exactly the scopes it needs, for example
  someone who may change firewall policies but not the network, or only block devices. A changed role
  applies at once, and the web UI hides what a role may not do.

**Network**

- **BGP and OSPF** (Network → Routing): exchange routes with other routers, a provider or a cloud,
  with FRR. Announce only what you choose, filter what you accept; a learned default route never takes
  your internet traffic. Every commit checks FRR's configuration before it goes live. See the wiki page
  *Dynamic Routing: BGP and OSPF*.
- **Site-to-site VPN** (VPN → Sites): join two or more gates into one private network by pasting a
  pairing code, without typing a WireGuard key. Each site is a zone in policies, nothing crosses until a
  policy allows it, and a site can be reached through another (hub and spoke). See the wiki page
  *Site-to-Site VPN*.
- **Captive portal** (Network → Captive portal): a welcome page on a guest network, with click-through,
  a shared password or voucher codes you print, a speed limit per guest, and your own title, terms and
  logo. It runs on the box, with no cloud or controller. See the wiki page *Captive Portal*.
- **RADIUS and dynamic VLANs** (Network → RADIUS): switches and Wi-Fi access points ask the gate who may
  connect and which VLAN each device belongs in. MAC authentication for printers and TVs, 802.1X with a
  password or with a certificate the gate issues, a quarantine VLAN for unknown devices, and a Wi-Fi
  password per device for access points that support it. **Move to VLAN** under Network → Devices takes
  effect at once: the gate tells the switch to reconnect the device. Recent authentications show the
  result, the reason, and the switch port or access point. See the wiki page *RADIUS and Dynamic VLANs*.
- **UniFi plugin** (`goblin-gate-plugin-unifi`): shows under Network → Devices where each device is
  connected (switch and port, or access point and Wi-Fi network), and keeps live address objects filled
  with the clients of a UniFi network or Wi-Fi network. It only reads from your controller. Other plugins
  can add device details too. See the wiki page *UniFi*.

**Automation**

- **Terraform and OpenTofu provider:** manage VLANs, DHCP static leases, local DNS records, addresses,
  services, policies and port forwards as code. Each apply step is one commit with a comment that says
  what changed, optionally with a confirm timer; the provider stops if someone else has uncommitted
  changes, and existing objects can be imported. The provider is attached to this release for Linux,
  macOS and Windows (`terraform-provider-goblingate_0.4.0-beta.1_<os>_<arch>.zip`); its README explains
  how to install it. The new wiki page *Automation* shows the same homelab set up with Terraform, with
  curl and with Ansible.

## Fixed

- **Updates on a box running a beta while its channel is stable** failed every time with "the installed
  version … could not be saved for a rollback". The updater now also finds the installed version in
  apt's cache or in the beta suite, and when it really can't, it says which channel to pick (also in 0.3.0).
- Everything fixed in 0.3.0.
- The captive portal and RADIUS settings no longer drop something typed right after the page opens.

## Upgrading

Boxes on the beta channel see this version within 6 hours (System → Updates, or `apt-get update &&
apt-get install goblin-gate` as root). The update also installs FRR and FreeRADIUS, which run only once
you turn on BGP/OSPF or RADIUS; if your box skips recommended packages, install them with
`apt-get install frr frr-pythontools freeradius freeradius-rest`. Debian's own FreeRADIUS service stays
off: the gate runs its own. No reboot is needed. For the UniFi plugin, run
`apt-get install goblin-gate-plugin-unifi`, then enable it under System → Plugins.

## Try it without installing

```
docker run --rm -p 127.0.0.1:8090:8090 ghcr.io/mostlywithinspec/goblin-gate-demo
```

Then open http://localhost:8090.

## Install

Download `goblin-gate-0.4.0-beta.1-amd64.iso` below, boot it (BIOS or UEFI, Secure Boot works), pick the
disk, and open `https://<LAN address>` to run the setup wizard.
