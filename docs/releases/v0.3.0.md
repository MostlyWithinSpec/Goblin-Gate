Goblin Gate 0.3.0, the third stable release, for homelabs.

It is the same code as 0.3.0-beta.1.1, which has run as a home firewall since the first 0.3.0 beta came out,
plus one fix for the updater. If you're coming from 0.2.0, this is what's new:

## New since 0.2.0

- **Live address objects:** a new address type whose members a plugin keeps up to date at runtime, without
  a commit. Use it in policies and groups like any other address. A plugin needs the new `objects:write`
  capability for it, every change is in the audit log, and the policy simulator matches the current
  members. See the wiki page *Objects*.
- **Proxmox and Docker plugin** (`goblin-gate-plugin-homelab`): turns the VMs and containers of a Proxmox VE
  cluster and of Docker hosts into live addresses. Tag a guest `gg-web` (or match it by name) and it is in
  the address `web` while it runs, with its current address. Proxmox is read with a read-only API token,
  Docker over TLS with a client certificate. If a hypervisor can't be reached, the objects stay as they
  were. See the wiki page *Homelab*.
- **Internal CA** (Network → Reverse Proxy → Certificate authority): the gate keeps a private certificate
  authority. Trust its root once on each device, and reverse proxy hosts with names inside your network
  (such as `nas.home.lan`) get trusted certificates, while your NAS, Proxmox or any ACME client can get its
  own certificates from an ACME directory that only the LAN can reach. See the wiki page *Internal CA*.
- **Flow export** (Log & Report → Flow export): send the box's connections to a flow collector as NetFlow v9
  or IPFIX over UDP, for long-term traffic history in tools such as ntopng, Elastiflow or GoFlow2. Nothing
  extra runs on the box. See the wiki page *Prometheus and Grafana*.
- **Plugin SDK:** a Go package (`pkg/pluginsdk`) for writing plugins, with an example plugin in
  `plugins/hello` and a walkthrough in `docs/dev/plugins.md`. The Sentry and Home Assistant plugins now run
  on it.
- **AppArmor:** Suricata and Caddy run under their own enforcing AppArmor profiles, and Unbound and Kea
  under Debian's, so a flaw in one of them can't reach the rest of the box. If you point one of them at a
  file of your own from the shell, see *Troubleshooting* on the wiki for the local overrides.

## Fixed

- **Downloads through the IPS** no longer stall and fail: a connection Suricata can't follow completely
  carries on, and only IPS rules drop traffic (since 0.3.0-beta.1.1).
- **DHCP with AppArmor installed:** the Kea config check now runs where Debian's Kea profile allows it to
  read (since 0.3.0-beta.1).
- **Updates on a box running a beta while its channel is stable** failed every time with "the installed
  version … could not be saved for a rollback". The updater now also finds the installed version in apt's
  cache or in the beta suite, and when it really can't, it says which channel to pick. System → Updates
  also says when a beta on the stable channel waits for the next stable release.

## Upgrading

Boxes on the stable channel see 0.3.0 within 6 hours. Update from System → Updates, or on the box as root:

```sh
apt-get update && apt-get install goblin-gate
```

The update also installs AppArmor and loads the new profiles. No reboot is needed. If the new version
doesn't come back healthy within 5 minutes, the box reinstalls the previous one on its own. For the Proxmox
and Docker plugin, run `apt-get install goblin-gate-plugin-homelab`, then enable it under System → Plugins.

A box installed from a 0.3.0 beta ISO and left on the stable channel still runs the old updater, which shows
the rollback error above for this update. Run the two commands above on it once as root; from then on
System → Updates works.

## Install

Download `goblin-gate-0.3.0-amd64.iso` below, boot it (BIOS or UEFI, Secure Boot works), pick the disk, and
open `https://<LAN address>` to run the setup wizard.

## What's next

New features go to the beta channel first, as 0.4.0 betas: single sign-on and custom admin roles, BGP and
OSPF, site-to-site VPN between gates, a captive portal, RADIUS with a VLAN per device, UniFi device details,
and a Terraform / OpenTofu provider. Fixes for 0.3.0 come as 0.3.x on stable.
